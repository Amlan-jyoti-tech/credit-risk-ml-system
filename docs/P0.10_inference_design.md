# P0.10 — Production Integration & Inference Architecture Design

**Status:** DESIGN ONLY — awaiting approval before implementation  
**Phase:** P0.10  
**Depends on:** P0.7 (frozen baseline), P0.8 (explainability audit), P0.9 (calibration)  

> [!IMPORTANT]
> This document is a **design specification only**. No Python code, no FastAPI routes, no Docker files, no model retraining, and no artifact modification has been performed.

---

## 1. Current Architecture Assessment
The current system consists of a batch ML pipeline:
- **Feature Engineering:** `src/features/build_features.py` defines `FeatureEngineer` which learns medians, bounds, and scalers during `fit()`.
- **Frozen Baseline (P0.7):** `src/models/xgboost_baseline.joblib` (135 features) and `logistic_regression_baseline.joblib` (168 features).
- **Explainability (P0.8):** Post-hoc analysis artifacts in `results/feature_importance/`.
- **Calibration (P0.9):** Isotonic regression calibrators in `results/calibration/` (e.g., `p09_calibrated_xgb_isotonic.joblib`).

## 2. P0.10 Goals and Non-Goals
**Goals:**
- Design a production-style inference prototype / ML engineering portfolio implementation.
- Expose the frozen XGBoost + P0.9 Isotonic Calibration model via a REST API.
- Ensure strict separation of Validation, Feature Engineering, Inference, Calibration, and Policy.

**Non-Goals:**
- Do NOT build a real production lending system.
- Do NOT claim optimal credit decision, best model, regulatory compliance, or fairness certification.
- Do NOT retrain models, refit preprocessing, or recalibrate.

## 3. Current Feature Engineering Behavior
`FeatureEngineer` learns parameters during `.fit()` (from training data only):
- Medians for 35 columns (`imputation_medians`).
- 99.5th percentile caps for `annual_inc` and `dti` (`capping_thresholds`).
- Expected dummy column structures.
- Imputation values (Max+1 or -1) for delinquency fields.

`transform()` applies these fixed parameters, derives `fico_score` and `credit_history_months`, flags missingness, applies log-transforms, scales (for LR), and one-hot encodes.

## 4. Single-Application Inference Compatibility
**Critical Inference Requirement Analysis:**
Can the current `FeatureEngineer` safely transform one raw loan application using exact training-learned transformations?
**Answer:** Yes, but the fitted `FeatureEngineer` used for P0.7 was never serialized to disk. 

The API must NEVER fit `FeatureEngineer` at runtime. The API must NEVER learn medians, caps, scalers, categorical mappings, or feature ordering from an incoming request. 

Since the original fitted state was not persisted, it must be deterministically reconstructed from the exact P0.6 training data and the existing `FeatureEngineer` implementation. We will introduce a one-time script (`scripts/serialize_feature_pipeline.py`) to reconstruct and serialize the training-fitted feature pipeline to `artifacts/feature_engineer_xgb.joblib`. 

**Mandatory Verification Checkpoint:**
We cannot assume reconstruction is identical to the original run. Before the reconstructed artifact is accepted, a programmatic verification must assert:
`Frozen XGBoost expected features == Serialized/reconstructed inference feature schema`
This verification must confirm:
- Exact feature count (135)
- Exact feature names
- Exact feature order (`xgb_model.feature_names_in_`)
- Transformation parameters match what is expected by the frozen XGBoost model.

If exact equivalence cannot be demonstrated safely from the current repository, this is a blocker, and the inference pipeline cannot safely proceed.

## 5. Proposed Inference Architecture
```
Loan Application Request (JSON)
      ↓
[Input Validation - Pydantic]
      ↓
[Feature Engineering - Frozen FeatureEngineer]
      ↓
[Model Inference - Frozen XGBoost]
      ↓
Raw Default Probability
      ↓
[Probability Calibration - Frozen P0.9 Isotonic]
      ↓
Calibrated Default Probability
      ↓
[Decision / Policy Layer - Optional, Configurable]
      ↓
API Response (JSON)
```

## 6. Feature Transformation Flow
1. **Raw Dict:** Received from API request.
2. **DataFrame:** Converted to 1-row Pandas DataFrame.
3. **FE Transform:** The reconstructed `fe_xgb.transform(df, model_type='xgb')` is called (NO `.fit()` is called).
4. **Alignment:** Ensure the resulting columns exactly match `xgb_model.feature_names_in_` in count and order.

## 7. Frozen XGBoost Model Integration
- **Artifact:** `src/models/xgboost_baseline.joblib`
- **Integration:** Loaded at startup. Call `raw_prob = xgb_model.predict_proba(X_transformed)[:, 1]`.
- XGBoost handles NaNs natively for the 8 specific columns that had missing values in training.

## 8. P0.9 Isotonic Calibration Integration
- **Artifact:** `results/calibration/p09_calibrated_xgb_isotonic.joblib`
- **Integration:** Loaded at startup. Call `calibrated_prob = iso_model.predict([raw_prob])[0]`.
- **Constraint:** The calibration object must NEVER be refitted during inference.

## 9. Input Contract
The API accepts only origination-time information.
- **Required:** `loan_amnt`, `term`, `int_rate`, `installment`, `sub_grade`, `home_ownership`, `annual_inc`, `verification_status`, `dti`, `addr_state`, `purpose`, `application_type`, `fico_range_low`, `fico_range_high`, `earliest_cr_line`, `issue_date` (needed to compute credit history), plus other core origination fields.
- **Optional:** Fields with learned median/zero imputations (e.g., `emp_length`, `pub_rec_bankruptcies`).

## 10. Forbidden / Leakage Fields
The API must strictly reject (HTTP 422) any post-origination information, including:
`loan_status`, `default_flag`, `total_pymnt`, `total_pymnt_inv`, `total_rec_prncp`, `total_rec_int`, `recoveries`, `collection_recovery_fee`, `last_pymnt_d`, `last_pymnt_amnt`, `next_pymnt_d`, `last_fico_range_high`, `last_fico_range_low`, `last_credit_pull_d`, and all hardship/settlement fields.

## 11. Input Validation
- **Tool:** Pydantic models with `extra='forbid'` to reject unknown/leakage fields.
- **Rules:** Value ranges (e.g., `loan_amnt > 0`, `int_rate > 0`), valid enums, non-negative bounds.
- **Chronological Check:** `earliest_cr_line` ≤ `issue_date`.

## 12. Output Contract
The primary prediction output is `calibrated_default_probability`.
```json
{
  "raw_default_probability": 0.482,
  "calibrated_default_probability": 0.192,
  "model_name": "xgboost_baseline",
  "model_version": "P0.7",
  "calibration_method": "IsotonicRegression",
  "risk_band": "MODERATE",
  "disclaimer": "ML engineering portfolio implementation. Not a production lending system."
}
```

## 13. Decision / Policy Layer
- A completely separate, optional Python module (`app/policy.py`).
- Maps `calibrated_default_probability` to a configurable string label (e.g., "LOW", "MODERATE", "HIGH").
- This does NOT represent a real credit decision or leverage P0.9 illustrative cost thresholds as production rules.

## 14. FastAPI Architecture
- `GET /health`
  - **Purpose:** Liveness probe.
  - **Response:** `{"status": "ok"}`
- `GET /model-info`
  - **Purpose:** Expose artifact metadata and pipeline version.
  - **Response:** JSON with model versions, features, bounds.
- `POST /predict`
  - **Purpose:** Score a single loan application.
  - **Request:** JSON matching input schema.
  - **Response:** JSON matching output schema.
  - **Validation:** Pydantic.
  - **Errors:** 422 (Validation), 500 (Internal Inference Error).

## 15. Error Handling
- **422 Unprocessable Entity:** Missing fields, invalid types, forbidden/leakage fields included.
- **500 Internal Server Error:** Model fails to load, `transform()` crashes, mismatch in feature count.
- **Security:** Do not expose Python stack traces or internal local filesystem paths to the client.

## 16. Testing Strategy
- **Validation:** Valid input, missing required, missing optional, invalid numeric, invalid categorical, range errors.
- **Leakage Guard:** Explicit test confirming P0.4 leakage fields are rejected.
- **Inference:** Deterministic identical input yields identical output, probability in `[0,1]`, no NaNs in final features, exact feature count (135) and order.
- **Endpoints:** Integration tests for `/health`, `/model-info`, `/predict`.
- **Note:** Do NOT use the P0.7 test set parquet for these tests. Use synthetic 1-row fixtures.

## 17. Model and Version Metadata
Lightweight JSON file (`artifacts/model_metadata.json`):
- `model_name`: xgboost_baseline
- `model_type`: XGBClassifier
- `training_phase`: P0.7
- `calibration_artifact`: p09_calibrated_xgb_isotonic.joblib
- `feature_pipeline_version`: P0.10
- Python & package versions (sklearn, xgboost, pandas).

## 18. Artifact Management
Frozen models remain in `src/models/` and `results/calibration/`. The newly serialized `feature_engineer_xgb.joblib` and `model_metadata.json` will be stored in a new `artifacts/` folder.

## 19. Docker Design
- **Base Image:** Minimal Python slim image (e.g., `python:3.11-slim`).
- **Inclusions:** `app/`, `src/`, frozen model `.joblib` files, `artifacts/`, `requirements.txt`.
- **Exclusions (`.dockerignore`):** The 1.6 GB raw dataset (`data/`), `.git`, `.env`, tests, notebooks. No secrets or credentials.

## 21. Model Card Design
`docs/model_card.md` will document: Intended use (portfolio prototype only), non-intended uses (real lending), data source (historical Lending Club), target definition, evaluation bounds, features, leakage controls, and known limitations (e.g., temporal drift, fairness unverified).

## 22. Inference Contract Design
`docs/inference_contract.md` will document: Exact JSON schema for requests, mandatory vs. optional fields, enumeration values, default imputation logic for missing fields, output payload structure, and HTTP status codes.

## 23. README Integration
The project `README.md` will be updated to include instructions for:
- Starting the FastAPI server locally (`uvicorn app.main:app`).
- Building and running the Docker container.
- Sending a sample `curl` request to `/predict`.

## 24. Security and Privacy
- `.dockerignore` prevents raw/processed loan datasets from entering the container.
- API logs must strictly avoid logging full loan application payloads to prevent PII leakage. Log only request IDs and status codes.
- The `.env` file (if any) must remain in `.gitignore`.

## 25. Reproducibility
- The inference logic relies on strictly frozen joblib artifacts.
- Deterministic preprocessing: The same input payload will always produce the exact same calibrated probability.
- Dependencies pinned in `requirements.txt`.

## 26. Performance Considerations
- The API is designed for single-row synchronous inference.
- Model artifacts are loaded into memory exactly once at startup (module-level cache or FastAPI lifespan event).
- Latency expectation: <100ms per request.

## 27. Risks and Mitigations
- **Risk:** Pydantic validation misses a leakage field. **Mitigation:** Use `extra='forbid'`.
- **Risk:** `FeatureEngineer` creates columns in a different order. **Mitigation:** Explicitly index `df[xgb_model.feature_names_in_]` before calling `predict_proba`.
- **Risk:** Missing `issue_date`. **Mitigation:** Enforced as required in Pydantic to compute credit history.
- **Risk:** Reconstructed FeatureEngineer state differs from the frozen model expectations. **Mitigation:** Mandatory verification checkpoint during serialization. 

## 28. Exact Implementation Order
1. **Phase 1: Feature Serialization.** Create `scripts/serialize_feature_pipeline.py`. Deterministically reconstruct the state using training data. Verify equivalence with frozen XGBoost. Serialize to `artifacts/feature_engineer_xgb.joblib` and `artifacts/model_metadata.json`. If equivalence cannot be verified, stop implementation. 
2. **Phase 2: Schemas & Validation.** Create `app/schemas.py`. Implement Pydantic models. Write `tests/` for validation and leakage fields.
3. **Phase 3: Core Inference.** Create `app/inference.py`. Wire FE, XGB, and Calibration. Write tests for deterministic inference.
4. **Phase 4: API & Policy.** Create `app/policy.py` and `app/main.py`. Wire endpoints. Write integration tests.
5. **Phase 5: Containerization.** Create `Dockerfile` and `.dockerignore`. Test image locally.
6. **Phase 6: Documentation.** Write `model_card.md`, `inference_contract.md`, and update `README.md`.
