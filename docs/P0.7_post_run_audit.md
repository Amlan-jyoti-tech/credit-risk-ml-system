# Phase 0.7: Post-Run Audit

This document verifies the methodological integrity of the Phase 0.7 baseline model training and evaluation process.

## 1. XGBoost Missing Values Handling
*   **Columns with NaNs:** During the training phase, the following 8 columns naturally exhibited a tiny fraction of missing values (~29 rows out of 453,809) in the XGBoost matrix: `acc_now_delinq`, `credit_history_months`, `delinq_2yrs`, `delinq_amnt`, `inq_last_6mths`, `open_acc`, `pub_rec`, `total_acc`.
*   **Intentional Preservation:** Rather than forcefully imputing these with zeros (which was done for Logistic Regression via the `StandardScaler` handling), they were deliberately preserved as `NaN` for XGBoost. Tree-based models like XGBoost handle sparsity natively, learning an optimal default branch direction for missing values during tree construction. This prevents introducing artificial bias (e.g., zero-imputation) when it isn't mathematically necessary.
*   **P0.5 Adherence:** The XGBoost matrix remained strictly bound to the 135 approved features. No new features, validation data, or target-derived information leaked into these columns.

## 2. Logistic Regression Path Integrity
*   **NaN Presence:** The Logistic Regression matrix (`train_lr`) contained exactly 0 NaNs.
*   **Preprocessing Leakage Check:** All `StandardScaler` bounds, means, and variances were exclusively learned from the Train matrix in P0.6 and securely applied without modifications during P0.7.

## 3. Threshold Selection Independence
*   **Validation Sweep:** Thresholds were evaluated between probability `0.1` and `0.9`. 
*   **Selection:** The final thresholds were selected strictly to maximize the Validation F1 Score:
    *   `Logistic Regression`: 0.50
    *   `XGBoost`: 0.45
*   **Zero Leakage:** The Test dataset was completely isolated during this sweep. The thresholds were selected before the `y_test_prob` was calculated or evaluated.

## 4. Hyperparameter and Class Weight Integrity
*   **`scale_pos_weight` Calculation:** The XGBoost weight was calculated dynamically via the script strictly as `Count(Train Non-Default) / Count(Train Default)`, evaluating to exactly `4.87`. Test labels were entirely isolated.
*   **Hyperparameter Tuning:** No hyperparameter grid search or random search was performed on the Validation or Test sets. The model utilized explicit, fixed conservative baseline parameters as instructed.

## 5. Terminology and Metric Rigor
*   **Confusion Matrix Wording:** The wording in `P0.7_model_results.md` has been audited and updated to strictly use standard technical terminology (True Negative, False Positive, False Negative, True Positive) coupled with neutral descriptors (e.g., "non-default correctly classified" rather than "approved good loan").
*   **PR-AUC Nomenclature:** PR-AUC is now explicitly annotated as Average Precision (`average_precision_score` in Scikit-Learn) to ensure unambiguous interpretation.

## 6. Baseline Class Prevalence
The true target (`default_flag = 1`) base rates are mathematically confirmed as:
*   **Train:** 17.03%
*   **Validation:** 14.89%
*   **Test:** 19.85%

## 7. Execution Order Integrity
The sequence of evaluation steps enforced in `p07_train_eval.py` strictly adhered to standard ML protocols:
1.  Model Fitting (Train exclusively)
2.  Prediction on Validation
3.  Threshold Selection (Validation F1 maximization)
4.  Model Freezing
5.  Prediction on Test
6.  Final Metric Generation

## 8. Final Audit Conclusion

The Phase 0.7 baseline run is **methodologically valid**. 

The handling of missing values, class weights, and threshold selection strictly adhere to data-isolation and anti-leakage principles. No methodological flaws, target leakage, or test-set peeking were discovered. 

These results are robust and can be officially adopted as the Tier-1 Performance Baseline. **No correction or re-run is required.**
