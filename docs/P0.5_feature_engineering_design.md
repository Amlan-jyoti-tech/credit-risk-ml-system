## 2. Design Decisions Summary

### 2.1 Compact Baseline vs. Full Feature Set

**Decision: Use a curated baseline feature set.**
We will use a curated set of **71 conceptual features**. Highly redundant features, high-cardinality geographic features (like `zip_code`), and schema-era features (with ~60% missingness) are deferred to Tier-2.

### 2.2 Encoding Strategies

*   **`addr_state`**: Target encoding is explicitly **EXCLUDED** from the Tier-1 baseline due to its complexity and leakage risk. For the baseline, `addr_state` will be **one-hot encoded** (50 dummies) for both Logistic Regression and XGBoost.
    *   *Future note:* If target encoding is tested later in Tier-2, it must be fit **only on training data**, use out-of-fold encoding during cross-validation, and never leak validation/test targets.
*   **`sub_grade`**: For Logistic Regression, imposing a linear relationship via ordinal encoding is risky. `sub_grade` will be **one-hot encoded** (34 dummies) for LR. For XGBoost, **ordinal encoding** is justified because tree-based models naturally handle non-linear monotonic relationships and ordinal encoding preserves the ordered nature of risk while reducing dimensionality.
*   **`emp_length`**: Kept as an ordinal feature for both models, as its ordering ("<1 year" to "10+ years") has a clear semantic and numerical interpretation.

### 2.3 Data Quality and Outliers

Based on an inspection of the actual data distributions:
*   **`revol_util`**: 4,714 rows (0.35%) are > 100%, with a max of 892.3%. These are not necessarily errors—borrowers can exceed their credit limit. We will leave these raw for XGBoost and evaluate capping at 100% or 150% during LR implementation.
*   **`dti`**: 
    *   `dti == -1`: 2 rows. Plausible if debt obligation is negative, but rare.
    *   `dti == 999.0`: 38 rows. Likely a sentinel value or input system cap.
    *   `dti == 0`: 881 rows. Borrowers with zero debt (plausible).
    *   `dti` is null: 374 rows.
    *   We will explicitly impute nulls with the median (learned from the train set) and evaluate capping the `999.0` sentinel during implementation.
*   **`annual_inc`**: 
    *   `annual_inc == 0`: 361 rows. Valid state (unemployed or co-signer).
    *   `annual_inc` is null: 4 rows.
    *   `annual_inc` > $1,000,000: 291 rows.
    *   We will impute nulls with the median and log-transform for LR to handle the extreme right skew. Zero values and nulls are distinct and handled separately.

### 2.4 Informative Missingness

Missingness in certain fields is highly informative (e.g., missing `mths_since_last_delinq` implies no delinquency).
We will create **6 explicit missingness indicators**:
1.  `emp_length_missing`
2.  `has_prior_delinq` (from `mths_since_last_delinq`)
3.  `has_public_record_history` (from `mths_since_last_record`)
4.  `has_major_derog` (from `mths_since_last_major_derog`)
5.  `has_bc_delinq` (from `mths_since_recent_bc_dlq`)
6.  `has_revol_delinq` (from `mths_since_recent_revol_delinq`)

**Imputation Strategy:**
*   For these 5 delinquency fields, nulls will be imputed with a large constant (e.g., maximum training value + 1 for LR, or -1 for XGB) to separate them from recent delinquencies.
*   **CRITICAL:** All imputation statistics (median, mode, max+1) must be calculated **using the training split ONLY** and applied to validation/test sets to prevent data leakage.

### 2.5 Installment, Interest Rate, and Sub-Grade

*   `installment` is largely deterministic from loan amount, interest rate, and term.
*   `int_rate` and `sub_grade` are highly correlated since pricing depends on the grade.
*   We will **keep all of them in the baseline**. Redundancy and multicollinearity will be diagnosed during the implementation phase (e.g., using VIF for Logistic Regression). No features will be removed solely based on pre-modeling assumptions of correlation.

## 3. Input vs. Output Schema

The feature engineering pipeline transforms raw parquet columns into model-ready matrices. The exact counts are rigorously separated to avoid ambiguity.

| Schema Stage | Count | Description |
| :--- | :--- | :--- |
| **A. Raw Parquet input selected** | **66** | 66 columns pulled from the parquet file for the baseline. |
| **B. Raw columns replaced** | **3** | `fico_range_low`, `fico_range_high`, `earliest_cr_line` are dropped and replaced. |
| **C. Raw columns retained directly** | **63** | 66 - 3 = 63 raw columns passed through. |
| **D. Derived features** | **2** | `fico_score` and `credit_history_months`. |
| **E. Missingness indicators** | **6** | Binary flags indicating null values in specific fields. |
| **F. Final Conceptual Features** | **71** | 63 (retained) + 2 (derived) + 6 (indicators) = 71 conceptual features before encoding. |

### Final Encoded Dimensionality

**G. Logistic Regression Matrix Dimensions:**
*   **Numeric:** 56 (54 raw + 2 derived)
*   **Binary:** 9 (3 raw + 6 indicators)
*   **Ordinal:** 1 (`emp_length`)
*   **One-Hot:** 102 (3 for `home_ownership` + 2 for `verification_status` + 13 for `purpose` + 50 for `addr_state` + 34 for `sub_grade`)
*   **Total LR Dimensions:** 56 + 9 + 1 + 102 = **168 dimensions**

**H. XGBoost Matrix Dimensions:**
*   **Numeric:** 56 (54 raw + 2 derived)
*   **Binary:** 9 (3 raw + 6 indicators)
*   **Ordinal:** 2 (`emp_length`, `sub_grade`)
*   **One-Hot:** 68 (3 for `home_ownership` + 2 for `verification_status` + 13 for `purpose` + 50 for `addr_state`)
*   **Total XGB Dimensions:** 56 + 9 + 2 + 68 = **135 dimensions**

**I. Metadata:**
*   `id`, `issue_d` (used for joining and temporal splitting, NOT as features).

**J. Target:**
*   `default_flag`
