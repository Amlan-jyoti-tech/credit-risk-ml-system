## 2. Prediction Point

| Element | Value |
|---|---|
| **Prediction point** | Loan origination / credit decision |
| **Target** | `default_flag` |
| **Target meaning** | `0` = observed non-default outcome (Fully Paid or equivalent) |
| | `1` = observed default outcome (Charged Off / Default or equivalent) |
| **Decision context** | At the moment Lending Club makes the credit/pricing decision |
| **Implication** | Only information available at or before origination may be used as a predictor |

### 2.1 Prediction Point Timing Distinctions

| Timing | Description | Examples |
|--------|-------------|---------|
| **Pre-origination** | Information available when the borrower applies | `annual_inc`, `emp_length`, `purpose`, credit bureau pulls |
| **At origination** | Information determined by LC's credit model or at the moment of approval | `grade`, `sub_grade`, `int_rate`, `loan_amnt`, `term` |
| **During/after funding** | Information finalized after the loan is listed or funded | `funded_amnt_inv` (investor commitment), `disbursement_method` |
| **Post-origination** | Information generated during the repayment lifecycle | All payment, recovery, hardship, settlement, and updated FICO fields |

## 7. Prediction-Point Timing Audit

### 7.1 Safe at Origination

| Column | Evidence | Classification |
|--------|----------|---------------|
| `grade` | Determined by LC's credit model at the time of origination. This IS the credit decision output. | **SAFE** |
| `sub_grade` | Same as `grade`, finer-grained. | **SAFE** |
| `int_rate` | Set by LC based on `sub_grade` at origination. Deterministic from the credit decision. | **SAFE** |
| `installment` | Deterministic function of `loan_amnt` + `int_rate` + `term`. Verified: mean computational diff is 0.14–0.60, confirming it's purely derived. | **SAFE** |
| `initial_list_status` | Set when the loan is listed. This occurs at or near origination as part of the listing process. The listing status is part of how LC markets the loan. | **SAFE** |

### 7.2 Borderline

| Column | Evidence | Classification |
|--------|----------|---------------|
| `funded_amnt` | 99.85% identical to `loan_amnt`. Only 2,062 differences (0.15%), exclusively in 2007–2013. Since ~2014, LC fully funds loans at origination. Differences reflect historical partial-funding which has been discontinued. | **BORDERLINE** — functionally redundant with `loan_amnt` |
| `funded_amnt_inv` | 8.66% of rows differ from `loan_amnt`. Differences span all years (2007–2018). Min value is 0.0 (loans with no investor funding). Finalizes after listing when investors commit. | **BORDERLINE** — post-listing, not available at credit decision |
| `disbursement_method` | Cash (1,341,199) vs DirectPay (6,900). Determined at disbursement, after approval. | **BORDERLINE** — post-approval |

### 7.3 Decision

For a conservative origination-time model:

## 10. Corrected Temporal Evaluation Strategy

### 10.1 Candidate Strategies

#### Strategy A: All-Term Fully Mature Only (Most Conservative)

| Split | Cohorts | Approx. Rows | Justification |
|-------|---------|-------------|---------------|
| **Train** | 2007–2012 (all terms) | ~104,902 | All cohorts fully contractually mature, 0% exclusion |
| **Validation** | 2013 (all terms) | ~134,804 | Fully mature (0–0.03% exclusion), chronologically next |
| **Test** | 2014/36m + 2015/36m | ~445,596 | Fully mature 36-month cohorts, 0–0.05% exclusion |

- **Advantages:** Completely trustworthy labels across all splits. No survivorship bias. Both terms in train.
- **Limitations:** Train set is small (105K). Does not test on most recent data. Test set is only 36-month loans. 2007 is anomalous (financial crisis, 26% default rate, 603 loans).
- **Risk of selection bias:** Minimal — all cohorts are fully resolved.

#### Strategy B: Mixed Maturity, 36-Month Only for Test (Pragmatic)

| Split | Cohorts | Approx. Rows | Justification |
|-------|---------|-------------|---------------|
| **Train** | 2007–2014 (all terms) | ~453,402 | 2014/36m fully mature; 2014/60m has 17.15% exclusion but ~83% of loans are resolved — acceptable for training (bias mitigated by having other fully-mature 60m cohorts) |
| **Validation** | 2015/36m | ~283,026 | Fully mature (0.05% exclusion) |
| **Test** | 2016/36m | ~232,361 | 28.17% exclusion; partially mature. Retained 36m loans from 2016 had up to 28 months of observation — most defaults on 36m loans occur within 18 months. Usable with documented caveat. |

- **Advantages:** Larger train set (453K). Reasonable chronological ordering. Test set is the most recent cohort with somewhat defensible labels for 36-month loans.
- **Limitations:** Train includes 2014/60m (17.15% exclusion); test includes 2016/36m (28.17% exclusion). Some survivorship bias in test set — "Current" loans that were performing well at snapshot time are excluded, potentially inflating observed default rate.
- **Risk of selection bias:** Moderate in test set. The 2016/36m cohort has 28.17% exclusion, and retained loans may skew toward faster outcomes.

#### Strategy C: Fixed Performance Window (Re-derive Target)

Define: "Did the loan default within the first 24 months of origination?"

| Split | Cohorts | Approx. Rows | Justification |
|-------|---------|-------------|---------------|
| **Train** | 2007–2015 (all terms, 24-month window) | ~553K+ | Any loan with ≥24 months of observation |
| **Validation** | 2016 (all terms, 24-month window) | ~293K+ | Loans issued Dec-2016 have 27 months of observation by Mar-2019 |
| **Test** | 2017-H1 (all terms, 24-month window) | ~96K+ | Loans issued Jun-2017 have 21 months; Jan-2017 has 26 months |

- **Advantages:** Consistent target definition across all periods. Uses more recent data. Both terms included.
- **Limitations:** Requires re-deriving the target using `issue_d` and `last_pymnt_d`/outcome dates. Changes the prediction task from "will this loan ever default?" to "will this loan default within 24 months?" 60-month loans that default in months 25–60 would be misclassified as non-default.
- **Risk of selection bias:** Low within the observation window. But truncates long-term defaults.

> [!IMPORTANT]
> Strategy C would require explicit re-definition of `default_flag`, which is a substantive change to the prediction task. Do NOT implement without explicit approval.

### 10.2 Recommended Strategy

**Strategy B is the most defensible pragmatic choice for this project.**

**Rationale:**
1. Train set includes all terms from 2007–2014 (~453K loans), providing enough volume and diversity.
2. 2014/60m inclusion in training is acceptable: 83% of loans are resolved, and the model will see both 36m and 60m default patterns from fully-mature earlier cohorts.
3. Validation on 2015/36m provides a clean, fully-mature chronological holdout.
4. Test on 2016/36m, while having 28% exclusion, is the latest cohort where 36-month loans had ~28 months of observation (sufficient for most defaults to manifest). The survivorship bias should be documented and reported alongside metrics.
5. **All 2017 and 2018 data should be excluded from standard evaluation** due to >59% exclusion rates.
6. **60-month loans from 2015+ should be excluded from validation/test** due to incomplete maturity.

**This strategy should NOT be presented as "production-valid."** It is the best available approach given the data limitations, with documented caveats about partial maturity in the test set.

## 15. Explicit Leakage Prevention Rules

1. **Only information available at loan origination may be used as a predictive feature.** No payment performance, repayment status, or post-issuance credit data may enter the feature matrix.

2. **Any variable generated from subsequent payments or loan performance must be excluded.** This includes all `total_pymnt*`, `total_rec_*`, `out_prncp*`, `recoveries`, `collection_recovery_fee`, `last_pymnt_*`, and `next_pymnt_*` fields.

3. **Any variable containing post-origination credit behavior must be excluded.** This includes `last_fico_range_*` and `last_credit_pull_d`.

4. **Target-derived information must never enter the feature matrix.** `debt_settlement_flag`, `settlement_*`, and `hardship_*` fields encode post-origination events that are consequences of (or strongly correlated with) the default outcome.

5. **Identifiers are not predictive features unless there is a documented business reason.** `id`, `member_id`, and `url` must be excluded from the feature matrix.

6. **Temporal evaluation must prevent future information from entering training.** Train/validation/test splits must be chronological. No loan from a later time period may appear in an earlier split.

7. **Test set labels must be trustworthy.** Cohorts with extreme exclusion rates (>50%) should not be used for standard evaluation because retained labels are survivorship-biased. The test set must document its exclusion rate and any associated bias.

8. **Zero-variance features must be excluded.** `pymnt_plan` and `policy_code` carry no information.

9. **Redundant features should be documented and handled during feature engineering.** This is an information-efficiency concern, not a leakage concern.

10. **Borderline-timing features should be excluded from the baseline model** unless a documented business justification establishes they were available at credit decision time.

## 16. Limitations and Unresolved Issues

### 16.1 Temporal Limitations

- **No cohort from 2016 onward is fully contractually mature** for both 36-month and 60-month terms.
- The recommended test set (2016/36m) has **28.17% unresolved loans excluded**, meaning the test set is not a random sample of 2016 originations. Metrics on this set should be reported alongside the exclusion rate.
- **60-month loans from 2014 onward** have progressively higher exclusion rates (17%→33%→45%→67%→90%). Any evaluation of 60-month loan predictions on recent data is fundamentally compromised.

### 16.2 Target Definition Limitations

- The target uses the **final observed status** at the ~March 2019 snapshot. A fixed observation window (e.g., 24-month default) would be more rigorous but requires re-deriving the target (Strategy C). This would change the prediction task.
- **Survivorship bias** in recent retained cohorts: retained loans from 2017–2018 are disproportionately "fast outcomes" — either very fast payoffs or very fast defaults.

### 16.3 Data Quality Issues

- `annual_inc`: 4 null values; min = 0.0 (zero income reported)
- `dti`: 374 nulls; max = 999.0 (extreme outlier)
- `revol_util`: max = 892.3 (extreme outlier, likely data error)
- 2007 cohort: only 603 loans with 26.20% default rate (financial crisis + tiny sample)

### 16.4 Open Business Decisions

1. **`funded_amnt` / `funded_amnt_inv` / `disbursement_method`**: Currently classified as borderline. Need business confirmation of timing relative to credit decision.
2. **Joint application features**: Exclude from baseline, or conditionally merge with primary applicant fields?
3. **Schema-era features (~60% null)**: Include with null-indicator imputation, or restrict training to post-2015 data only?
4. **`installment`**: Deterministic from other features — include for convenience or drop to reduce collinearity?
5. **`grade` vs `sub_grade`**: Both safe, but `grade` is fully subsumed by `sub_grade`. Keep both or only `sub_grade`?
