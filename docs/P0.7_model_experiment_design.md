# Phase 0.7: Model Experiment Design

## 1. Objective
Train and evaluate initial baseline models for credit-risk prediction (default classification) at the point of loan origination. The experiment focuses on establishing a robust baseline using the fully audited and leakage-free P0.5/P0.6 temporal datasets.

## 2. Models

We will train two primary models:

### 2.1 Model 1: Logistic Regression
*   **Purpose:** Provide an interpretable, linear baseline.
*   **Input Data:** `data/processed/temporal_splits/train_lr.parquet` (168 dimensions, scaled numeric features, one-hot encoded categoricals).
*   **Configuration Strategy:** 
    *   No extensive hyperparameter tuning.
    *   `max_iter` will be increased (e.g., to 1000 or 5000) to ensure convergence on the large dataset.
    *   `random_state=42` for reproducibility.
    *   L2 regularization (Ridge) with default `C=1.0` as a starting point.
    *   `class_weight='balanced'` to handle the inherent class imbalance.

### 2.2 Model 2: XGBoost Classifier
*   **Purpose:** Provide a non-linear, tree-based benchmark capable of capturing complex interactions without manual feature crosses.
*   **Input Data:** `data/processed/temporal_splits/train_xgb.parquet` (135 dimensions, unscaled numeric features, ordinal sub-grades).
*   **Configuration Strategy:**
    *   Conservative baseline: `n_estimators=300`, `max_depth=5`, `learning_rate=0.1`.
    *   Regularization: `reg_alpha=0.1`, `reg_lambda=1.0`.
    *   Subsampling: `subsample=0.8`, `colsample_bytree=0.8` to prevent overfitting.
    *   `min_child_weight=10` to prevent isolating very small leaf nodes in a dataset of ~453K rows.
    *   `random_state=42`.
    *   `scale_pos_weight` will be calculated explicitly from the training set (`count(non-default) / count(default)`).

## 3. Data Strategy and Class Imbalance

**Temporal Split Policy:**
*   **Train (2007–2014):** Strictly used for model fitting and calculating class weights.
*   **Validation (2015 36m):** Strictly used for model comparison, metric calculation, and threshold selection.
*   **Test (2016 36m):** Frozen holdout. Will be evaluated exactly once per model using the final locked configuration and threshold.

**Target Prevalance:**
*   The positive class (Default = 1) is the minority class.
*   Training set default rate is ~17.03%.
*   We will strictly avoid synthetic resampling (like SMOTE) in this baseline phase and rely solely on algorithmic class-weight adjustments.

## 4. Evaluation Metrics

Because of the class imbalance (majority non-default), accuracy is a highly misleading metric (a naive model predicting all zeros would achieve ~83% accuracy but zero utility). We will evaluate models based on:

1.  **ROC-AUC (Receiver Operating Characteristic Area Under Curve):** Measures overall ranking ability across all thresholds.
2.  **PR-AUC (Precision-Recall Area Under Curve / Average Precision):** A more robust summary metric for imbalanced positive-class identification.
3.  **F1 Score:** Harmonic mean of precision and recall at the selected threshold.
4.  **Precision:** Out of all loans predicted as default, what fraction actually defaulted? (Critical for minimizing false positives).
5.  **Recall:** Out of all true defaults, what fraction did the model successfully identify? (Critical for minimizing false negatives).
6.  **Confusion Matrix:** Raw counts of True Positives, False Positives, True Negatives, and False Negatives.

## 5. Threshold Selection Strategy

The standard `0.5` probability threshold is rarely optimal for imbalanced classification with differing business costs.

1.  **Sweeping:** We will evaluate validation metrics at probability thresholds from `0.1` to `0.9` (in increments of 0.05).
2.  **Selection Criterion:** For this baseline experiment, we will select a threshold that maximizes the **F1 Score** on the validation set. 
    *   *Business Caveat:* Maximizing F1 assumes false positives and false negatives carry roughly equal cost, which is rarely true in consumer lending (the cost of funding a bad loan usually far exceeds the opportunity cost of rejecting a good one). A production system would select a threshold optimizing a specific financial profit-loss function (e.g., expected return based on loan size and recovery rates).
3.  **Freezing:** The selected threshold will be locked alongside the model and applied blindly to the Test set.
