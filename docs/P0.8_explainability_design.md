## 3. What Explainability Means for Each Model

### 3.1 Logistic Regression (168 dimensions)

LR coefficients **are** the explanation. For a linear model, the coefficient vector is a complete, exact, global explanation of model behavior. No approximation is needed.

**What we will extract:**

| Analysis | Method | Notes |
|:---|:---|:---|
| **Signed coefficients** | Direct from `lr.coef_[0]` | Already extracted; 168 values |
| **Intercept** | Direct from `lr.intercept_[0]` | Value: -1.2570 |
| **Coefficient magnitude ranking** | `np.argsort(np.abs(coefs))` | Top-N by absolute value |
| **Coefficient direction** | Sign of each coefficient | +positive → increases P(default), −negative → decreases P(default) |
| **One-hot reference categories** | Documented from `drop_first=True` | See Section 4.1 |
| **Transformation-aware interpretation** | Manual annotation | See Section 4.2 |

**Why LR coefficients are sufficient:**
- LR is a *linear* model in the transformed feature space
- Each coefficient represents the change in log-odds of default per one-unit change in the (transformed, standardized) feature, holding all other features constant
- No approximation method (LIME, SHAP) can improve upon exact coefficients for a linear model — they would simply recover the same coefficients

### 3.2 XGBoost (135 dimensions)

XGBoost is a non-linear ensemble of 300 trees. There is no single coefficient vector. Multiple complementary importance measures are needed.

**What we will extract:**

| Analysis | Method | Notes |
|:---|:---|:---|
| **Gain-based importance** | `booster.get_score(importance_type='gain')` | Mean gain across all splits using each feature. **Preferred metric** — measures actual contribution to loss reduction. |
| **Weight (split frequency)** | `booster.get_score(importance_type='weight')` | How often each feature is used as a split. Biased toward high-cardinality features but useful as a secondary check. |
| **Permutation importance** | `sklearn.inspection.permutation_importance` on validation set | Model-agnostic. Measures actual predictive value by shuffling each feature. Computationally expensive but robust to the gain/weight biases. |
| **Zero-importance features** | Features never used in any tree | Already identified: 8 features (7 rare states + `application_type`) |

**Why gain-based importance is preferred over weight:**
- Weight counts splits, which biases toward continuous features (many possible split points) and high-cardinality features
- Gain measures the actual reduction in the objective function, which is what we care about
- Our inspection confirmed: `sub_grade` ranks #1 by gain (1077.3) but only #11 by weight (214), because each `sub_grade` split is highly informative even though continuous features get more splits

## 4. Logistic Regression Interpretation Details

### 4.1 Reference Categories (drop_first=True)

When `pd.get_dummies(drop_first=True)` is used, the first category in each group is dropped and becomes the **reference**. All coefficients for that group are *relative to the reference*.

| Feature Group | Reference (Dropped) Category | Dummies Present | Interpretation |
|:---|:---|:---|:---|
| `home_ownership` | **MORTGAGE** | OWN, RENT, OTHER | Coef for `RENT` = effect *relative to MORTGAGE* |
| `verification_status` | **Source Verified** | Not Verified, Verified | Coef for `Verified` = effect *relative to Source Verified* |
| `purpose` | **debt_consolidation** | 13 other purposes | Coef for `small_business` = effect *relative to debt_consolidation* |
| `addr_state` | **CA** | 50 other states | Coef for `NY` = effect *relative to CA* |
| `sub_grade` | **A1** | A2 through G5 (34 dummies) | Coef for `G5` = effect *relative to A1 (safest grade)* |

> [!IMPORTANT]
> **This means LR coefficients for one-hot features are NOT absolute effects.** The coefficient for `purpose_small_business` (+0.688) means small business loans have +0.688 higher log-odds of default *than debt_consolidation loans*, holding other features constant. It does NOT mean small business loans have a 0.688 log-odds increase in absolute terms.

### 4.2 Feature Transformations Affecting Interpretation

Every LR coefficient must be interpreted in the context of its transformation chain. The P0.8 script will annotate each feature with its transformation.

| Transformation | Features Affected | Interpretation Impact |
|:---|:---|:---|
| **StandardScaler** | All 56 numeric features | Coefficient is per-standard-deviation change. A coefficient of +0.5 means "one SD increase → +0.5 change in log-odds." Magnitudes are **directly comparable** across standardized features. |
| **log1p** + StandardScaler | `annual_inc`, `revol_bal`, `tot_cur_bal`, `avg_cur_bal`, `bc_open_to_buy`, `total_bc_limit`, `total_bal_ex_mort`, `tot_hi_cred_lim`, `total_il_high_credit_limit`, `total_rev_hi_lim`, `tot_coll_amt` (11 features) | Coefficient is per-SD of log1p(capped_value). The relationship to raw dollars is non-linear. A +1 SD increase in log-income does not correspond to a fixed dollar amount. **Must note "log-scale" in all interpretations.** |
| **Capping** (99.5th pctl) | `annual_inc` (capped at $300K), `dti` (capped at 36.27) | Extreme values are compressed. The model cannot distinguish incomes above $300K. |
| **Hard cap** | `revol_util` (capped at 100%), `bc_util` (capped at 100%) | Over-limit behavior is lost. |
| **Ordinal encoding** | `emp_length` (0–10 scale) | Coefficient assumes linear relationship between employment length and log-odds. One year increase = same effect whether 1→2 or 9→10. |
| **Binary encoding** | `term` (0=36m, 1=60m), `application_type`, `initial_list_status` | Direct interpretation: coefficient = full effect of being in category 1 vs. category 0. |
| **Missingness indicators** | 6 binary flags (`has_prior_delinq`, etc.) | Coefficient = effect of having a delinquency history on record vs. having none. |
| **Informative imputation** (max+1) | 5 `mths_since_*` fields | Null values imputed with train max+1 (e.g., 189 for `mths_since_last_delinq`). These imputed values are then standardized. The imputed value represents "no such event" and will be at the extreme high end of the distribution. |
| **One-hot encoding** | `sub_grade` (34 dummies), `addr_state` (50), `purpose` (13), `home_ownership` (3), `verification_status` (2) | Coefficient = effect relative to dropped reference category. See Section 4.1. |

### 4.3 What We Expect to See (Sanity Checks)

Based on credit-risk domain knowledge, these coefficient patterns would be **plausible**:

| Expected Pattern | Feature | Expected Sign | Rationale |
|:---|:---|:---|:---|
| Higher sub-grades → more default | `sub_grade_G5` vs A1 | ✅ Large positive | G5 is highest risk grade |
| 60-month term → more default | `term` | ✅ Positive | Longer exposure period |
| Higher income → less default | `annual_inc` | ✅ Negative | Greater repayment capacity |
| Higher FICO → less default | `fico_score` | ✅ Negative | Better credit history |
| Small business → more default | `purpose_small_business` | ✅ Positive | Higher risk purpose |
| Higher DTI → more default | `dti` | ✅ Positive | More debt burden |

**Patterns requiring investigation** if observed:
- Any state dummy with very large magnitude (possible overfitting to geographic noise)
- `int_rate` with unexpected sign (should be positive, but may be suppressed by multicollinearity with `sub_grade`)
- Missingness indicators with very large magnitude (possible artifact)

## 5. XGBoost Interpretation Details

### 5.1 Gain vs. Weight vs. Permutation

| Method | What It Measures | Bias | When to Trust |
|:---|:---|:---|:---|
| **Gain** | Average loss reduction per split | Biased toward features with many unique values (continuous) | Best single metric for "which features reduce prediction error most" |
| **Weight** | Number of times a feature is used for a split | Strongly biased toward continuous features (more split points available) | Secondary check; if a feature has high weight but low gain, it's splitting frequently but not helpfully |
| **Permutation** | Drop in validation metric when feature is shuffled | Unbiased; model-agnostic | Gold standard for "which features does the model actually need"; detects features that are important only through interactions |

### 5.2 Preliminary Findings from Inspection

From the scratch inspection (not modifying anything):

**XGB Top 5 by Gain:**
1. `sub_grade` — gain 1077 (ordinal; dominant feature as expected)
2. `term` — gain 569 (binary; longer term = more default)
3. `int_rate` — gain 218 (continuous; not redundant with sub_grade for XGB)
4. `emp_length_missing` — gain 118 (**potential concern** — missingness as a signal)
5. `acc_open_past_24mths` — gain 105 (recent account openings)

**8 features with zero importance** (never used in any tree):
- `addr_state_IA`, `addr_state_ID`, `addr_state_ME`, `addr_state_ND`, `addr_state_NE`, `addr_state_RI`, `addr_state_SD` (all low-population states)
- `application_type` (nearly all Individual in training data)

**Items requiring investigation in P0.8:**
1. `emp_length_missing` at #4 is suspicious. It means "employment length was not reported." This could be a legitimate signal (self-employed/unemployed applicants don't report) or an artifact. The P0.8 report must flag this.
2. `addr_state_CO` at #14 is unusually high for a single state. Needs to be checked for data artifact vs. genuine geographic signal.
3. `int_rate` and `sub_grade` are both in the top 3. In LR, `int_rate` may be suppressed by multicollinearity with `sub_grade`, but XGB can use both non-linearly.

### 5.3 XGBoost Encoding Differences

Unlike LR, XGBoost uses **ordinal encoding** for `sub_grade` (0–34 integer). This means:
- `sub_grade` appears as a single feature (vs. 34 dummies in LR)
- Gain concentrates into one feature instead of being distributed across 34 dummies
- Direct comparison of "most important feature" between LR and XGB requires aggregating the 34 LR sub_grade dummies

### 5.4 Permutation Importance Configuration

```python
from sklearn.inspection import permutation_importance

# Configuration
perm_result = permutation_importance(
    model,           # frozen XGB model
    X_val,           # validation features only
    y_val,           # validation labels
    n_repeats=10,    # 10 random shuffles per feature
    random_state=42, # reproducibility
    scoring='roc_auc',  # same metric used in P0.7 evaluation
    n_jobs=-1        # parallel
)
```

**Why permutation importance on validation set:**
- It does NOT retrain the model (uses frozen model as-is)
- It does NOT modify the model's internal state
- It measures "how much does the model's prediction quality degrade when this feature's relationship to the target is broken?"
- Using validation set (not train) avoids overfitting-inflated importance

**Note:** We will also compute permutation importance for LR as a cross-check against coefficients. For a well-specified linear model, permutation importance should broadly agree with coefficient magnitude.

## 6. Dataset Split Strategy for Explainability

### 6.1 Which Split for Which Explanation

| Explanation Type | Dataset | Rationale |
|:---|:---|:---|
| **LR coefficients** | N/A (extracted from model object) | Coefficients are global; no dataset needed |
| **XGB gain/weight importance** | N/A (extracted from booster object) | Tree structure is global; no dataset needed |
| **Permutation importance** | **Validation** (2015/36m, 283K rows) | Large enough for stable estimates; temporally forward from train; not the test set |
| **Feature distribution summaries** | **Validation** (2015/36m) | Provides context for interpreting coefficients |
| **Suspicious feature investigation** | **Train + Validation** | May need to examine train distributions to understand learned patterns |

### 6.2 Why NOT the Test Set for Explanations

> [!CAUTION]
> The test set was evaluated exactly once in P0.7. Using it for explanations creates a risk: if we observe something in the test-set explanations and use that observation to guide future modeling decisions (Tier-2 feature selection, hyperparameter changes, etc.), we have effectively leaked test-set information into the modeling process.

**Rule:** The test set is off-limits for P0.8 explanations. All global explanations use the validation set. If a separate "explanation holdout" were desired, it would need to be carved from training data — but for Tier-1, validation is sufficient.

### 6.3 Exception: Test-Set Explanation Report (Optional)

A **read-only test-set explanation report** (e.g., "here is what the model predicted on test") is acceptable ONLY if:
1. It is generated AFTER all modeling decisions are locked
2. It is clearly labeled as "post-hoc observation, not input to any decision"
3. It does not influence any future phase

**Recommendation: Defer test-set explanations to a final summary report after all Tier-1 phases are complete.**

## 8. SHAP Decision: Defer to Tier-2

### 8.1 Arguments FOR Including SHAP in P0.8

- SHAP provides instance-level explanations (which features drove *this specific* prediction)
- SHAP summary plots are visually compelling and interview-friendly
- SHAP handles feature interactions that gain-based importance misses

### 8.2 Arguments AGAINST Including SHAP in P0.8

| Concern | Detail |
|:---|:---|
| **Computational cost** | TreeSHAP on 283K validation rows × 135 features × 300 trees is expensive (~5-15 min). Not prohibitive, but adds complexity. |
| **Marginal value for Tier-1** | For a *baseline* with ROC-AUC 0.70, the primary question is "did the model learn sensible patterns?" — not "explain individual predictions." Gain + permutation importance answer the global question sufficiently. |
| **Interpretation complexity** | SHAP values require careful explanation (they are not "how much this feature contributed" in a simple additive sense — they are Shapley values from cooperative game theory). For a Tier-1 report, this adds more confusion than clarity. |
| **Risk of over-interpretation** | With 283K SHAP values per feature, it's easy to mine for patterns that look significant but are noise. For a Tier-1 baseline, this is premature. |
| **No model change will follow** | P0.8 does not change models. SHAP's value is highest when it informs feature engineering or model debugging — which is Tier-2 work. |

### 8.3 Recommendation

**Defer SHAP to Tier-2** (when we have better models worth explaining in detail). For P0.8, gain + permutation importance + LR coefficients provide a complete, defensible, interview-ready explanation.

If SHAP is later added, it should use `shap.TreeExplainer` for XGB (exact, polynomial-time) and `shap.LinearExplainer` for LR (exact, closed-form). Both use the frozen model objects without retraining.

## 9. Distinction: Explanation vs. Causation vs. Business Interpretation

### 9.A — Explanations of Model Behavior

> "The model assigns higher default probability to loans with sub_grade G5 compared to A1, holding other features constant."

This is a statement about **what the model learned**. It is factual and verifiable from the coefficient/importance values.

### 9.B — Causal Claims (PROHIBITED)

> ~~"Having a G5 sub-grade *causes* a borrower to default."~~

This is a causal claim. The model cannot establish causation. Sub-grade is itself a risk assessment by Lending Club — it *encodes* perceived risk, it doesn't *cause* default. Including such claims would be methodologically wrong and interview-indefensible.

### 9.C — Business Interpretation (Permitted with Caveats)

> "The model's reliance on sub_grade as its top feature is expected, since LC's grading system is specifically designed to predict default risk. The model is effectively learning to refine LC's existing risk stratification."

This is a contextual interpretation that connects model behavior to domain knowledge without claiming causation. It is appropriate for a Tier-1 report.

**Every feature interpretation in the P0.8 output will be labeled A, B, or C to maintain rigor.**

## 14. Known Interpretation Challenges

### 14.1 Sub-Grade Dominance

Both models are dominated by `sub_grade`. This is expected (LC's grading system is a sophisticated credit model itself), but it means:
- LR: 34 of the top 20 coefficients by |magnitude| are sub_grade dummies
- XGB: `sub_grade` has 6× the gain of the next feature (`term`)

The P0.8 report will present importance both **with and without sub_grade** to reveal what the model learns beyond the grading system.

### 14.2 Multicollinearity in LR

`int_rate` and `sub_grade` are highly correlated (pricing is determined by grade). In LR:
- `int_rate` coefficient: +0.137 (modest)
- This is because `sub_grade` dummies absorb most of the risk-pricing signal
- The `int_rate` coefficient captures only the residual effect not explained by sub_grade

This is NOT a problem — it's expected behavior of multicollinear features in regularized LR. The P0.8 report will document this explicitly.

### 14.3 Log-Transformed Features

For the 11 log1p-transformed features, the LR coefficient must be interpreted as:
> "A one-standard-deviation increase in log1p(capped_value) is associated with a [coefficient] change in log-odds of default."

This is technically correct but not intuitive. The P0.8 report will provide:
- The coefficient (exact, technical)
- A qualitative direction statement ("higher income → lower default probability")
- A note that the relationship to raw dollars is non-linear

### 14.4 `emp_length_missing` as #4 in XGB

This is the most suspicious finding. The missingness indicator for employment length is the 4th most important XGB feature (gain=118). Possible explanations:
1. **Legitimate:** Self-employed or unemployed borrowers don't report `emp_length`, and these groups have genuinely different default rates
2. **Artifact:** Missingness correlates with application vintage (earlier years had more missing data) rather than credit risk
3. **Proxy:** Missing `emp_length` is a proxy for borrower engagement/diligence

The P0.8 report will investigate this by examining default rates stratified by `emp_length_missing` in the training data.
